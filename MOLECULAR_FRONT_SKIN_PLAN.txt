======================================================================

5. EXPANDING NODE MENUS
======================================================================

THIS IS IMPORTANT.

Clicking a control node should expand MORE NODES around it.

Example:

                    ○ Claude
                   /
        ○ Grok --- ○ AI Access --- ○ Mistral
                   \
                    ○ Cursor

The exact children must reflect existing available state where practical.

AI ACCESS NODE
Click:
- expand child nodes/options around AI Access
- examples:
  - Connected AIs
  - Connect AI
  - Revoke / Disconnect
  - On-device AI
- child-node actions invoke existing AI Access/provider UI/logic
- do not build a second provider system

SETTINGS NODE
Click:
- expand child nodes such as:
  - Motion
  - Labels
  - Pulses
  - Recenter
  - Workspace View
- presentation settings only unless safely invoking an existing settings surface

PROPOSALS NODE
Click:
- expand proposal-related nodes or badges
- examples:
  - Pending count
  - Review proposals
- actual review uses existing proposal data/UI

CONTEXT NODE
Click:
- expand options such as:
  - View current context
  - Copy context
- invoke existing context logic

ADD MEMORY NODE
Click:
- either open existing Add Memory dialog immediately
OR
- expand simple child nodes if useful
- must use existing memory creation flow

RULE:
Only one control branch needs to be expanded at once in the first prototype.
Opening a second control branch can collapse the previous branch.

6. NODE MENU BEHAVIOUR
======================================================================

Control subnodes should:
- emerge smoothly from their parent
- remain connected visually to the parent
- use the same projected coordinate system as the graph
- not use a separate physics engine
- be anchored/kinematic if necessary
- collapse smoothly when dismissed

Prefer radial / orbital expansion around the parent.

Do not let control-node menus disturb the actual memory-node physics.

======================================================================
7. FRONT-SKIN CONTROLLER RULE
======================================================================

The molecular skin controls EXISTING systems.

Examples:

AI Access control node
    -> trigger/open existing AI Access functionality

Add Memory control node
    -> trigger existing Add Memory flow

Memory node
    -> trigger existing inspector

Context node
    -> trigger existing context view

Proposal node
    -> trigger/focus existing proposal review

Do not duplicate:
- forms
- providers
- storage
- permission rules
- proposal logic
- memory lifecycle

If an existing system has no clean callable function, use the safest adapter:
- trigger its existing button
- dispatch its existing event
- expose the smallest wrapper hook

Do not rewrite the system.
