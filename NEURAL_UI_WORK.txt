    - index.html was still loading memory-graph-neural-spoke-mask.js?v=1 although the actual file is VERSION 2.

    - current width loader still references memory-graph-neural-arms.js?v=1 while arms is VERSION 4.
    - current width loader still references memory-graph-neural-terminal.js?v=1 while terminal is VERSION 3.
    - current mask loader still references memory-graph-neural-spoke-bundle.js?v=1 while bundle is VERSION 2.

    Consequence:
    - local files were being pulled correctly, but browser URL versions were stale and could continue serving cached renderer generations.
    - therefore recent patches could exist on disk/GitHub without producing a reliably new visual result.

    Fix applied in index.html only:
    - memory-graph-neural-width.js?v=13
    - memory-graph-neural-arms.js?v=4 loaded directly after width
    - memory-graph-neural-terminal.js?v=3 loaded directly after arms
    - memory-graph-neural-spoke-bundle.js?v=2 loaded directly before mask
    - memory-graph-neural-spoke-mask.js?v=2
    - memory-graph-neural-spokes.js?v=5

    Why direct loads are used:
    - they bypass the stale internal query strings without rewriting the working loader architecture.
    - install guards in each renderer prevent duplicate execution when the old dynamic loader later sees the already-loaded global.
    - this is an integration/cache patch only; no visual geometry or graph behaviour changed.
